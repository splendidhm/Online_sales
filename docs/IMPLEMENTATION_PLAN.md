# 단계별 개발·중간점검

## 현재 위치

**가격 정책 변경.** 현재 계산서와 승인 기준은 [시장조사 기반 가격 기준](SCORING_MODEL.md)을 따른다. 아래의 목표 마진·광고비·반품비 관련 체크 항목과 검산 사례는 이전 계산서 버전의 개발 이력이다.

2026년 11월 11일 기준 0단계 설계본을 작성했다. 1단계 구현은 다음 작업이다. 실제 호출·계정 권한·상품별 손익은 미검증이다. 점검할 때마다 완료 항목, 실행 환경과 재현 방법, 실패 항목, 다음 작업을 이 문서에 갱신한다.

0단계 자체 점검에서 한국어 문서 9개의 로컬 링크를 확인하고 원본 프롬프트의 업무 상태 24개, 외부 인터페이스 7개, 데이터 엔터티 25개를 설계본과 대조했다. 14,900원 예시의 공헌이익 3,510원·23.6%와 공급가 상승 시 19.5%를 별도 산술 계산으로 확인했다. 이 점검의 대상은 문서와 예시 계산이다.

| 단계 | 실행 순서 | 대표자에게 보여줄 중간 결과 |
|---|---|---|
| 0 설계 | 사업 범위 → 공식 연동표 → 상태·계산·계약 → 인수 사례 | 9개 문서와 네 가지 보완점 대조 |
| 1 상품 선별 | 한국어 웹·API·DB → 후보·중복 필터 → 실표본 입력 → 원가 계산 → 1차 승인 | 먼저 후보 1개에 대한 중간 계산서를 확인한 뒤 시범 회차 최대 10개를 검토 |
| 2 제작·검수 | 권리 근거 연결 → 원본 기반 초안 → 별도 QA → 채널별 미리보기 → 2차 승인 | 수치·인증·이미지 문구 오류 사례, 수정 전후와 승인된 게시본 |
| 3 마켓 등록 | 모의 게시 → 스마트스토어 한 상품 → 쿠팡 → 승인된 G마켓 | 채널마다 승인가·옵션·배송비·재고 재조회 결과, 실패한 채널 재시도 |
| 4 운영 | 재고·가격 감시 → 주문·반품 수집 → 정산 대조 → 기간 보고 | 실제와 예상 공헌이익 차이, 대조 실패한 정산행, 일간 알림과 주간 보고 |

## 개발 의존성과 비용

**1단계 첫 중간점검용 구현.** 저장소 루트의 [상품 한 개 계산서](../index.html)를 브라우저에서 연다. 연습 계산서에서 공급가를 6,000원에서 6,600원으로 바꾸고 결과를 비교한다. 실상품 계산서는 빈 값으로 시작하며 자료 종류·채널마다 한 장씩 같은 브라우저에 저장한다. 각 마켓의 판매자 표본 5건을 입력하면 추천가와 가격 경쟁강도를 확인할 수 있다. 계산 검증 명령은 `node --test calculator.test.js`다. 이 중간점검은 독립 HTML 화면이며 서버 DB, 회차 관리, 평가 이력, 대표자 승인은 후속 구현 범위다.

1단계는 Windows 작업 환경, Node.js·npm, Python 런타임, PostgreSQL 접속, 웹과 API를 실행할 로컬 설정이 필요하다. 의존 버전과 DB 마이그레이션을 프로젝트에 고정한다. 2단계에서는 AI 공급자 또는 모의 생성기와 S3 호환 저장소, 작업량에 따라 Linux 작업자·Redis를 연결한다. 운영 API 키는 3단계 실상품 등록에 사용한다. 1,000개 후보에 AI를 일괄 호출하지 않고 규칙 필터를 먼저 실행하며 입력 버전이 같은 작성·검수 결과를 재사용한다.

## 1단계 구현 체크리스트

**후보 비교와 1차 결정 중간점검.** Node.js 24 환경에서 프로젝트 폴더의 터미널로 `node server.js`를 실행하고 표시된 관리자 주소를 연다. 계산서를 작성해 ‘현재 계산서 저장’을 누른 뒤 목록의 ‘열기’로 저장 버전을 확인한다. 실상품은 공급 링크와 옵션을 기준으로 묶고 자료 종류별 최대 10개 후보를 비교한다. 공급 조건 확인·유효 표본·목표 마진 조건을 충족하면 ‘진행’을 저장할 수 있다. ‘보류’와 ‘제외’도 해당 버전에 기록한다. 수정 후 저장하면 새 버전을 검토한다. 두 채널은 각각 결정한다.

이 시연은 기존 계산 코드와 Node 내장 SQLite를 사용하며 데이터 파일은 `data/candidates.sqlite`에 보관한다. 로컬 서버는 127.0.0.1에 바인딩하고 실행 시 생성되는 개인 관리자 링크로 인증한다. 재시작하면 새 링크를 사용한다. 직접 연 HTML의 기존 계산서는 브라우저 저장소에 남으며 서버에서는 별도로 입력한다. 자동 검증은 `node --test calculator.test.js server.test.js`로 실행한다. 이후 검증 대상은 대량 모의 수집·선별, 근거별 가중 평가와 실제 상품 인수 사례다.

- [ ] 1A. 한국어 후보 화면에서 1개 직배송 상품의 출처·공급가·옵션·배송비·권리 증거를 수동 입력한다. 같은 원천·옵션 재입력과 서로 다른 세트 수량을 구별한다.
- [x] 1B. 관리자 링크에서 ‘연습 계산서 → 도매 상품 모의 수집 → 모의 회차 생성’으로 실행한다. 1~1,000건을 수집하고 공급 상품·옵션별로 조사 대상, 순번 대기, 중복, 제외, 보완을 집계한다. 각 회차의 판정과 사유는 서버에 저장한다. 조사 대상 최대 10개를 연습 계산서로 열고 저장하면 회차 번호가 연결된다. 유효 후보가 없으면 조사 대상은 0개다. 검증 명령은 `node --test calculator.test.js sourcing.test.js server.test.js`다.
- [ ] 1C. 네이버·쿠팡에 직접 확인한 표본을 마켓별로 입력한다. 다른 구성·같은 판매자 중복은 제외하고 채택/제외 사유를 표시한다. 4곳과 5곳의 판정 경계를 확인한다.
- [ ] **중간 시연.** 대표자가 시험 상품의 공급가·배송비를 바꿔 예상 공헌이익과 추천가가 변하는지 확인한다. 기록한 자료와 계산 근거를 화면에서 다시 열 수 있어야 한다.
- [ ] 1D. 검산 사례 3,510원·23.6%, 음수 이익, 유료 배송, 판매자 할인, 수수료 중복, 세금 기준 혼합, 목표가 미달을 단위 테스트한다. 결측·0원 입력을 구분한다.
- [x] 1E. 2026-11-12 상품성 평가를 연결했다. 계산서에서 수요·공급사 신뢰도·차별성의 등급과 근거를 입력하고 후보를 저장한다. 후보 목록에서 채널별 경쟁강도·근거 충족률·종합 점수를 확인한다. 근거 하나를 지우고 다시 저장하면 종합 점수가 ‘평가 대기’가 되는지 확인한다. 자동 점검은 `node --test`로 실행한다. 실제 상품 자료를 사용한 대표자 인수는 별도로 남아 있다.
- [ ] 1F. 대표자의 진행·보류·제외, 권한 없는 요청 차단, 중복 클릭, 새 평가 생성 후 이전 승인 요청 거절, 재시작 후 이력 복구를 확인한다.
- [ ] **1단계 인수.** 운영 키 없이 자동 테스트가 통과하고, 별도 실자료 회차에서 대표자가 직접 확인한 상품 한 개를 입력해 배송포함 경쟁가·채널별 마진·근거를 보고 1차 결정을 저장한다. 실표본을 확보하기 전까지 현장 인수는 대기로 기록한다.

## 이후 단계의 회귀 점검

2026-11-12 상세페이지 제작 중간점검. 서버 실행 후 후보 목록의 ‘진행 → 상세페이지 제작’에서 승인된 구성과 가격을 확인한다. 원산지·품목 고시·배송 및 반품 안내, 사용 근거가 있는 제품 사진과 사진 속 문구를 입력해 저장한다. ‘항균’ 등 검수 대상 문구를 입력해 승인 차단을 확인하고, 수정·저장 후 승인본 HTML을 내려받는다. 사진은 PNG/JPEG 한 장(2MB 이하)이며 채널과 계산서 버전별로 게시본을 보존한다. 수정 전 승인본과 과거 원가 버전은 최신 게시본으로 사용할 수 없다.

기본 모드는 공급 사실을 조합한 초안과 규칙 검수다. 선택형 AI를 사용하려면 서버 환경에 `ACC_CONTENT_AI_URL`(채팅 완성 요청을 받는 HTTPS 주소), `ACC_CONTENT_AI_MODEL`(이미지 입력과 JSON 출력이 가능한 모델), 필요 시 `ACC_CONTENT_AI_TOKEN`을 설정한다. 연결 시 AI 문안 제안은 편집기에 반영되고 저장할 때 별도 요청으로 문구·사진을 검수한다. 상품 자료와 사진이 설정한 서비스에 전송된다. 실제 공급처 이미지 자동 수집, 실모델 응답 품질 및 마켓 실등록은 별도 현장 확인 대상이다.

| 단계 | 실패를 주입할 사례 | 기대 결과 |
|---|---|---|
| 2 | 인증 누락, 사용 불가 이미지, AI가 만든 효능 문구, 수정 후 이전 승인 재사용 | 원본 위치와 근거를 한국어로 표시. 중대 이슈 또는 버전 불일치 시 게시 차단 |
| 3 | 공급가 변경·품절, 조회 지연, 등록 타임아웃, 중복 클릭, 옵션가·배송비 불일치, 일부 마켓 반려 | 재승인 또는 보류, 기존 접수 조회, 해당 채널만 재시도. 일치한 판매 중 상품만 성공 집계 |
| 4 | 재고 급감, 취소·부분 반품, 정산 지연·불일치, 같은 정산행 재수집 | 경고 발생, 실제 손실 반영, 미대조 사유 표시, 중복 수익 차단 |

## 주요 위험과 0단계 검토 결론

시간이 가장 드는 작업은 1인 운영자의 경쟁 표본 수집이다. 시범 회차에서 후보별 조사 시간을 기록해 10개 운영 규모를 조정한다. 수수료·반품비를 누락하면 추천 가격이 낮아지므로 근거 없는 비용은 보완 상태로 둔다. 판매 가능성은 실판매 결과로 검증한다. 공급사 이미지 편집 권한, G마켓 승인 일정, 실계정 쿼터는 [연동 가능성 표](API_INTEGRATIONS.md)의 미확인 항목으로 추적한다.
