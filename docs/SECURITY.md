# 접근 권한·증빙·복구

## 권한과 비밀

대표자만 승인·철회·실행 설정을 변경할 수 있다. 모든 관리자 요청은 서버에서 로그인 상태·권한·대상 계정·현재 버전을 검사한다. 개발용 로컬 실행은 루프백으로 제한하고 원격 운영은 HTTPS와 관리자 인증을 적용한다. 브라우저 세션은 HttpOnly·Secure 쿠키, 변경 요청은 CSRF 방어를 사용한다.

실마켓 키는 서버 환경변수 또는 비밀 저장소로 주입한다. 동적으로 보관하는 자격증명은 별도 키로 암호화하고 DB에는 키 참조를 둔다. 프런트엔드 번들·URL 로그·오류 추적·감사 로그·AI 입력에서 토큰과 민감 정보를 제거한다. 시험용 설정에서는 실계정 쓰기 어댑터를 구성할 수 없게 한다.

## 승인·AI·저작물

- 승인과 감사 이벤트는 추가 전용 테이블에 저장하고 앱 역할의 갱신·삭제 권한을 제거한다. 취소·대체는 새 이벤트로 기록한다. 승인·작업 고유키와 버전 검사는 동시 요청에도 DB에서 보장한다.
- 공급사 텍스트·이미지 OCR·외부 링크의 내용은 분석 자료다. AI가 반환한 명령을 실행하지 않는다. 작성·검수 단계는 쓰기용 마켓 키와 승인 권한에 접근할 수 없다. AI 결과를 구조 검증하고 원본 증거를 대조한다.
- 재판매·이미지 사용·편집·대상 채널 허용 여부를 분리해 저장한다. 편집 권한이 불명인 사진은 변형하지 않는다. 중대 오류나 필수 고시 누락은 출판을 차단하고 수정된 버전에서 다시 검수한다.
- 공급 HTML은 허용된 서식·이미지로 정리한 뒤 미리보기로 제공한다. 서버의 외부 이미지 가져오기는 허용 공급처와 HTTPS 대상으로 제한하고 리디렉션·파일 형식·크기를 확인한다. 수동 조사 링크는 대표자가 여는 참조로 저장한다.

## 개인정보와 운영 장애

1~3단계는 경쟁가 표본과 상품 정보만 다루며 주문자 이름·주소·전화번호를 입력받지 않는다. 4단계 도입 시 주문 식별·이행에 필요한 최소 필드를 정하고 원본 응답은 기본 미보관으로 둔다. 거래·정산 증빙과 운영 로그는 별도 보존 정책을 적용한다. 운영 로그는 기본 30일, 사용 종료된 임시 생성물은 7일 후 정리한다. 승인·거래 증빙은 목적과 적용 의무에 따른 기간을 운영 전 확정하며 증빙에 주문자 연락처를 복제하지 않는다.

공급처·채널별 호출 속도를 제한하고 쿼터와 Retry-After를 반영한다. 실패를 재분류해 일시적 오류만 자동 재시도한다. 발주·환불 등 금전 작업은 초기에는 수동이다. 이후 도입 시 권한 정책, 금액 범위, 주문 고유키, 재확인 절차를 먼저 정의한다. DB 백업과 비공개 증빙 저장소의 복구 시험에는 같은 버전의 승인·등록번호·작업 이력이 함께 복원되는 사례를 포함한다.
