# 시스템 구조

## 실행 단위

브라우저의 한국어 관리자 웹(Next.js·TypeScript)이 FastAPI의 인증된 HTTP API를 호출한다. Python 백엔드는 상품, 조사, 가격, 승인, 콘텐츠, 게시, 운영 모듈을 한 코드베이스로 관리한다. PostgreSQL이 업무 기록의 원본이다. UI와 작업자는 동일한 도메인 명령 및 검증 로직을 사용한다.

1단계의 소량 입력·계산·승인은 동기 요청으로 처리한다. 2단계에서 LangGraph로 작성과 독립 검수를 연결하고 Pydantic으로 입출력을 검사한다. 이미지와 상세페이지 버전은 S3 호환 비공개 저장소에 보관한다. 2~3단계의 긴 작업은 Redis를 통해 Celery 작업자로 전달한다. Windows에서 편집하고 작업자는 Linux 환경(WSL2 또는 Linux 컨테이너)에서 실행한다. [Celery 공식 운영체제 안내](https://docs.celeryq.dev/en/stable/faq.html#windows)

## 업무 모듈과 의존성

| 담당 | 입력 → 출력 | 실행 기준 |
|---|---|---|
| SourcingAgent | 공급 상품·사용 조건 → 정규화 옵션·권리 근거·중복 후보 | 공급처별 규격을 공통 형식으로 변환. 확실한 중복만 자동 병합하고 원본 식별자를 보존 |
| MarketResearchAgent | 규격과 직접 입력한 표본 → 채널별 조사 스냅숏 | 세트 수량·배송 조건 대조, 부적합 표본은 사유와 함께 제외 |
| ScoringAgent | 조사·원가 정책 → 가격 시나리오·평가 근거 | 금액은 Decimal, 결측 신호는 미확인 |
| ContentAgent | 1차 승인과 증빙 → 상세페이지 버전 | 권한이 있는 소재만 사용, 이미지에 삽입된 문구도 검수 대상 |
| QualityAssuranceAgent | 생성본과 독립된 공급 근거 → 항목별 검수 결과 | 생성 프롬프트의 결론을 증빙으로 사용하지 않음 |
| PublishingAgent | 유효한 2차 승인 → 채널별 게시 작업과 독립 조회 | 게시와 조회 인터페이스 분리, 판매자 상품코드로 복구 |
| MonitoringAgent | 재고·가격·주문·정산 관측 → 알림·주간 보고 | 예상과 실현 공헌이익 분리, 확인된 판매 결과로 점수 조정안을 제안 |

## 저장과 복구

- 승인 저장과 게시 예약용 이벤트를 한 DB 트랜잭션에 기록한다. 전달 작업자가 미전달 이벤트를 큐에 싣고 중복 수신은 작업 고유키로 흡수한다. 재시작 시 DB에서 미완료 상태부터 재개한다.
- 공급 상품·옵션·콘텐츠·비용 정책·조사 시점에서 입력 버전을 만든다. 변경 없는 근거의 재분석을 생략하고 가격 또는 재고의 유효성이 필요한 시점에는 별도 재조회한다.
- 로그는 작업 추적 ID, 단계, 채널, 오류 분류, 시도 횟수를 공통으로 기록한다. 승인 대기, 자료 부족, 가격 불일치, 실패 원인을 화면에서 원본 작업까지 따라갈 수 있어야 한다.
- 외부 서비스 교체 지점과 호출 결과 형식은 [데이터 계약](DATA_CONTRACTS.md), 채널별 인증·조회 범위는 [연동표](API_INTEGRATIONS.md)를 따른다.
